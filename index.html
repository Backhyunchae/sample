코드를 읽는 일보다, 원하는 결과를 정하는 일이 중심이 됩니다

AI가 초안을 빠르게 만들고, 사람은 실행해 보며 방향을 조정합니다.

말로 설명

"로그인 화면을 만들고, 실패하면 빨간 안내문을 보여줘"처럼 원하는 동작을 일상 언어로 적습니다.

바로 실행

생성된 결과를 즉시 열어 봅니다. 마음에 들지 않으면 코드를 직접 고치지 않고 다시 말로 요청합니다.

대화로 개선

색상, 문구, 기능을 한 번에 하나씩 바꾸며 결과물을 원하는 모양으로 다듬어 갑니다.

아이디어에서 결과물까지, 네 번의 대화

1

목표를 한 문장으로 적기

누가 쓰는지, 무엇을 해결하는지 먼저 정합니다. 예: "팀원들이 점심 메뉴에 투표하는 웹페이지."

2

작은 버전부터 요청하기

모든 기능을 한꺼번에 요청하지 않습니다. 핵심 화면 하나를 먼저 만들게 하세요.

3

실행하고 느낌 확인하기

직접 눌러 보고 어색한 부분을 찾습니다. 오류가 나면 화면의 메시지를 그대로 AI에게 전달합니다.

4

한 가지씩 고쳐 반복하기

버튼을 더 크게, 모바일에서 한 줄로처럼 구체적인 수정 요청을 이어 갑니다.

전통적인 개발과 무엇이 다를까요?

전통적인 개발

  • 문법과 라이브러리를 먼저 학습
  • 직접 한 줄씩 작성하고 디버깅
  • 첫 결과물까지 며칠이 걸릴 수 있음
  • 코드 구조를 세밀하게 통제

바이브 코딩

  • 만들고 싶은 결과를 먼저 설명
  • AI가 초안을 쓰고 사람이 검토
  • 첫 결과물이 몇 분 안에 나옴
  • 빠른 실험과 프로토타입에 강함
